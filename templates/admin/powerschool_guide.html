Why there are three files

Transportation determines which students can be assigned to buses. The other two exports identify direct-student and guardian notification destinations. BrightArrow sources can contain sentinel contact IDs, duplicate pseudo-contact rows and empty placeholders; keep the files separated so the application can interpret each row by its source role. Never merge or repair them manually.

Blocking gate: verify Transportation first

Do not proceed when Transportation is header-only, contains no valid bus assignments, or has blank busnumber values. The importer will stop before staging thousands of secondary contact errors. A large contacts export cannot compensate for an incomplete Transportation export.

2. Run each export

  1. Open the saved template and confirm its name and data source match this guide.
  2. Confirm the PowerSchool context, school year and Export All Rows before every export.
  3. Keep the saved format: comma delimiter, CR/LF line endings, UTF-8, headers included and values quoted.
  4. Run the Transportation template before 6:00 PM; its PowerSchool source changes to the next service day after 6:00 PM.
  5. Save with the expected filename. Do not open and resave the CSV in Excel because stable IDs and leading zeroes can change.

3. Protect and verify the files

  • Treat every file as confidential student and guardian information.
  • Do not email, schedule, or place exports in a shared or public folder.
  • Confirm all three files were created on the same date and belong to the intended school year.
  • Open each file only with a plain-text/CSV viewer and compare the header to the downloadable contract; do not save it.
  • Transportation must contain a plausible population and populated student and bus values before upload.
  • Do not rename columns, delete identifiers, combine sheets, or edit individual records in the CSV.
  • If counts or scope are uncertain, stop and obtain a corrected export before selecting a complete district snapshot.

Do not replace source sentinel values. A Student Contacts row may legitimately use contact ID 0; the importer derives a non-PII student identity from its file role and student number. Guardian contact ID 0 is reserved for overlapping student-self rows and is never imported as a guardian; a nonblank relationship on that ID is reported as an anomaly. Rows containing only a student number are empty placeholders and are also ignored.

5. Analyze before importing

  1. Open the importer and enter the school year in YYYY-YY format.
  2. Use Delta for normal incremental work. Use Complete district snapshot only after proving the exports contain the full district population.
  3. Select PowerSchool saved templates, then upload Transportation, Student Contacts and Guardian Contacts in their labeled fields.
  4. Choose Analyze and normalize. Nothing is imported during analysis. A blocking preflight first verifies that Transportation contains usable assignments.
  5. Review every new, update, unchanged, duplicate, conflict and rejected classification. Filter and exclude any record that should not proceed.
  6. Save the exact selection, download the review report and reconcile: selected + excluded + rejected = total.
  7. Apply only after the responsible reviewer approves the plan. Absence from a file never authorizes deletion; deactivation candidates require separate explicit approval.
If the exact files were analyzed before, choose Open existing analysis to resume it, or Re-analyze against current state to create a separate immutable comparison using the current mapping and application data. Re-analysis never applies the earlier batch and never modifies the uploaded CSVs.

Annual completion record

Retain the final review report and audit reference according to district policy. Record the export date, school year, operator, reviewer, selected/excluded/rejected totals and batch status. Raw CSV files should not be retained outside the approved secure workflow.
